# Продуктовый маршрут

## Цель

Русскоязычный путь от нулевого опыта до самостоятельной разработки сервисов на Rust: понятная теория → практика → проекты → ревью → эксплуатация. Нельзя обещать middle после кликов по урокам: нужна доказанная самостоятельность.

## MVP (создан)

4 модуля/16 уровней. Примерно 2 часа знакомства с основами (не измерено на пользователях). Короткая теория, встроенный редактор, тесты, подсказки, XP/прогресс. Без штрафов за ошибки и рейтингов давления. Это стартовая вертикаль продукта.

## Следующая версия

- Учётные записи/OIDC, восстановление доступа, экспорт/удаление данных.
- Авторский CMS и review: стабильные IDs, версии тестов, prepublication QA.
- Ещё 40–60 коротких уровней foundations/intermediate, задачи разных форматов.
- Проверка понимания: объяснить borrowing/ошибку, изменить требование, найти дефект; не только пройти тест.
- Повторение с интервалами и короткий skill diagnostic.
- Надёжная очередь проверки, dedicated execution infrastructure, limiter и наблюдаемость.

## Продвинутая программа (план, не готовые уроки)

| Блок | Темы | Подтверждение навыка |
|---|---|---|
| Lifetimes/generics | bounds, trait objects, API libraries | библиотека с тестами и rustdoc |
| Async/concurrency | Tokio, Send/Sync, cancel, channels, backpressure | устойчивая очередь задач |
| Backend/DB | Axum, SQLx, SQL, transaction, auth, OpenAPI | API с несколькими пользователями |
| Engineering | architecture, tracing, profiles, CI, Docker, security | deploy + нагрузочный отчёт + runbook |
| Capstone | самостоятельная постановка и реализация | внешнее ревью и защита решений |

Рекомендуемые проекты: CLI трекер задач → async монитор → API каталога → production-подобный сервис бронирования с конкурентными транзакциями. Материалы должны проверять не одну счастливую ветку, а ошибки, границы, Unicode и безопасность.

## Рубрика готовности к самостоятельной работе

Оценивать по 0–3 (не знает / с помощью / самостоятельно / объясняет компромиссы): владение Rust, проектирование API, хранение данных, конкурентность, тесты, безопасность, эксплуатация, code review. Рубеж: минимум «самостоятельно» по всем критическим навыкам и внешняя защита capstone. Это внутренняя рубрика, а не гарантия должности или работы.

## Критерии готовности к public beta

- Наблюдения минимум за несколькими новичками: где они останавливаются, что непонятно.
- Все уровни имеют теорию, доступные hints, эталонное решение и отрицательные/граничные тесты.
- Реальный sandbox прошёл все ограничения, cleanup и failure tests на целевом хосте.
- Нет дублей XP, утечек чужих черновиков, client-side обхода progression.
- Доступность WCAG AA, ручная клавиатурная и screen-reader проверка; сейчас полная сертификация не выполнена.
- Выполнены production blockers из SECURITY.md.

Технологии выбраны за поддержку и прозрачность, а не ради списка модных инструментов. Redis, Kubernetes, vector DB, AI tutor и микросервисы не нужны, пока не доказана потребность.
