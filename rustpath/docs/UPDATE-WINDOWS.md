# Обновление v0.1 → v0.2 на Windows без потери прогресса

Обновление сохраняет существующие ID уроков, completion/XP, drafts и guest tokens. Новая миграция только добавляет bookmarks. Нельзя менять старую миграцию 001 или удалять Docker volume.

## 1. Найдите исходную папку

Откройте ту папку `rustpath`, в которой раньше запускали `docker compose up`. Там лежат `compose.yaml` и ваш `.env`. Запускайте дальнейшие команды в PowerShell из **этой папки**. Не запускайте новый архив из другой папки: имя Compose-проекта может измениться, и появится другая пустая БД.

## 2. Сделайте резервную копию

Пока старые контейнеры работают:

```powershell
docker compose exec -T db pg_dump -U rustpath rustpath | Out-File -Encoding utf8 .\rustpath-before-v02.sql
```

Убедитесь, что файл не пуст и команда не показала ошибку. SQL содержит ваши данные и черновики; не публикуйте и не присылайте его в чат. Сохраните копию старого архива и `.env` в приватном месте. Сам факт создания dump не заменяет проверку восстановления.

## 3. Замените исходники, не настройки

1. Распакуйте `RustPath-v0.2.zip` отдельно.
2. Внутри новой папки `rustpath` выделите её содержимое.
3. Скопируйте его **в старую папку rustpath**, согласившись заменить исходные файлы.
4. **Ваш старый `.env` должен остаться неизменным.** В архиве нового `.env` нет; есть только шаблон `.env.example`.
5. Не создавайте новые секреты и не удаляйте volume.

## 4. Пересоберите

```powershell
docker compose up --build -d
```

Миграция 002 применяется при запуске API. Откройте прежний **http://localhost:8080** в том же браузере. При необходимости Ctrl+F5 обновит интерфейс; это не удаляет cookie.

## 5. Проверьте результат

Должно быть 3 маршрута и 44 урока. В «Основы Rust» остаются прежние completion и XP. Закладки можно проверить через «Сохранить тему» → перезагрузка → «Повторение». Новые квизы работают даже без запуска rustc.

Если общий процент стал ниже — появились новые уроки, а не исчезли старые. Если весь прогресс пропал, сначала проверьте папку/имя Compose-проекта, адрес и cookie. **Не проходите всё заново и не удаляйте БД**, пока не проверили причину.

Диагностика:

```powershell
docker compose ps
docker compose logs --tail=100 api runner
```

Не публикуйте `.env`, токены или приватные SQL dumps.

## Откат

Верните исходники v0.1 **в ту же папку**, оставьте `.env` и выполните `docker compose up --build -d`. Таблица bookmarks может остаться: она не мешает v0.1. Обе версии используют ту же неизменённую миграцию 001. Не откатывайте БД удалением volume. Восстановление из SQL backup — отдельная операция, которую следует делать только с пониманием, какие текущие данные она заменит.
